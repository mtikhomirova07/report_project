# Управленческая отчётность 2026

Система автоматической еженедельной финансовой отчётности.
Работает локально на Mac, данные берёт с Яндекс.Диска, при ошибках
отправляет уведомления на email.

---

## Что делает система

1. **Каждый понедельник в 9:00** (через cron) автоматически скачивает Excel-файл `test_v2.xlsx` с Яндекс.Диска.
2. **Проверяет данные** — все ли нужные листы и колонки на месте.
3. **Сохраняет снимок** с датой и временем в `data/snapshots/YYYY-MM-DD_HHMM.xlsx`.
4. **Показывает данные** в Streamlit-дашборде с фильтрами, графиками и сравнением версий.
5. **Позволяет согласовать** версию отчёта (принятую руководством). При новой согласовации старая заменяется.
6. **При ошибке:**
   - Снимок **не создаётся** (старая история не портится).
   - Ошибка пишется в `data/logs/errors.log`.
   - На email приходит уведомление.
   - В дашборде показывается ошибка.

## Возможности дашборда

### Сайдбар

- 🔄 **Кнопка «Обновить данные»** — запустить загрузку в любой день.
- 📅 **Выбор недели** — система автоматически берёт последний отчёт в этой неделе.
- ⭐ **Статус версии:** Черновик / Пред-BR / BR. При выборе BR старая BR-версия автоматически становится Черновиком.
- 📊 **Сравнение** — показывается, с какой BR-версией идёт сравнение.
- 🔍 **Фильтры:**
  - Бизнес-юнит (БЮ) — фильтрует весь отчёт.
  - Мин. вероятность сделки — фильтр для страницы «Сделки».

### Страница «P&L»

- **Таблица P&L** с вложенностью:
  - Revenue → Backlog / Pipeline / Extra GAP
  - Прямые расходы → StaffCost / COGS
  - GP3 → SGA → EBITDA
- **Кварталы Q1–Q4** — пропорциональная разбивка от годового прогноза (демо). На реальных данных будут реальные цифры.
- **Строка «ИТОГО (ключевые)»** внизу таблицы — сумма по ключевым статьям.
- **GM%** (маржа GP3/Revenue) — под таблицей по 4 колонкам.
- **Кнопка «📥 Скачать отчёт в Excel»** — выгружает 5 листов: P&L, Выручка, Прямые, SGA, Сделки.
- **Кнопка «📋 Перейти к сделкам»** — переход на страницу «Сделки».
- **Детализация по кварталам** — 4 expander'а (Q1–Q4). Внутри — 3 месяца + итого за квартал.
- **График «Тренд»** — отклонение прогноза от плана по неделям. 7 показателей на выбор.
- **График «Динамика по неделям»** — 6 показателей на выбор: Revenue (общая / по типам), Прямые, SGA, GP3, EBITDA.

### Страница «Сделки»

- **Фильтры:** Менеджер, Тип сделки, Статус, Мин. вероятность.
- **Реестр сделок** с колонками:
  - ID_сделки, БЮ, SubBU, Менеджер, Заказчик
  - Тип_сделки, Этап
  - Сумма_сделки, Статус, Прогноз_подписания
  - Дата_заведения, План_старт
  - Вероятность, %
  - Взвешенная_Q1, Q2, Q3, Q4
- **Отсутствующие в Excel поля** (SubBU, Этап, Дата_заведения, План_старт) — заглушка «—».
- **Пагинация:** по 12 сделок на страницу.
- **Итого по выборке:** количество, сумма, взвешенная выручка.
- **Кнопка «← Вернуться в P&L»**.

## Как запускать

### Открыть дашборд

```bash
cd ~/Desktop/report_project
source .venv/bin/activate
streamlit run dashboard.py
```

Браузер: `http://localhost:8501`

### Обновить данные вручную

В дашборде — кнопка **«🔄 Обновить данные»**.

Или из терминала:
```bash
python loader.py
```

### Согласовать версию

1. В сайдбаре выбери нужную неделю.
2. Нажми **«BR»** — версия помечается как BR.
3. При следующей согласации новая версия **заменяет** текущую.

### Проверить логи

```bash
cat data/logs/loading.log     # все операции
cat data/logs/errors.log      # только ошибки
cat data/logs/cron.log        # запуски по расписанию
cat data/logs/LAST_ERROR.txt  # последняя ошибка
cat data/statuses.json        # статусы версий
```

## Как работает автообновление (cron)

Настроен `cron`: каждый понедельник в 9:00 автоматически запускается загрузчик.

```bash
crontab -l                    # посмотреть расписание
crontab -e                    # изменить
crontab -r                    # удалить
```

Если cron не работает — добавь его в **Full Disk Access**:
**System Settings → Privacy & Security → Full Disk Access**.

## Логика статусов версий

- **Черновик** — по умолчанию, не отсмотрена.
- **Пред-BR** — промежуточная версия, отсмотрена, но не финальная.
- **BR** — финальная, согласована руководством.

- BR-версия **только одна**. При новой согласации старая становится Черновиком.
- В таблице P&L «Prev. BR» берётся **только** из версии со статусом BR.
- Список хранится в `data/statuses.json`.

## Если что-то сломалось

### Ошибка «Токен Яндекс.Диска недействителен»

Токен истёк. Получи новый на https://yandex.ru/dev/disk/poligon/ и замени в `loader.py` переменную `TOKEN`.

### Ошибка «Файл /test_v2.xlsx не найден»

Файл переименован или удалён с Диска. Проверь https://disk.yandex.ru — `test_v2.xlsx` в корне.

### Ошибка «нет колонки X»

Структура данных на Диске изменилась. Снимок не создастся, старая история сохранена. Восстанови структуру и нажми «Обновить данные».

### Письма не приходят

1. Проверь `.env` — правильный пароль приложения.
2. Запусти `python notifier.py` — тест.
3. Проверь папку «Спам».
4. Пароль активируется не сразу — подожди 2–3 часа.

### Кнопка «Обновить данные» не работает

Проверь в терминале:
```bash
python loader.py
```
Если ошибка — она же покажется в дашборде.

### Cron не запускается

```bash
crontab -l
```

Если пусто — добавь заново:
```bash
(echo "0 9 * * 1 cd /Users/mariatihomirova/Desktop/report_project && /Users/mariatihomirova/Desktop/report_project/.venv/bin/python loader.py >> /Users/mariatihomirova/Desktop/report_project/data/logs/cron.log 2>&1") | crontab -
```
